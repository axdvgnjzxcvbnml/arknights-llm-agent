# SFT 方向调整说明

> 日期：2026-09-30
> 状态：方案待确认，未执行数据重做
> 触发：鹿乃指出原方案方向性错误

---

## 一、原方案的问题

### 1.1 原方案

用 MAA 作业站的专家作业作为 SFT 训练目标：
- 输入：游戏状态描述
- 输出：专家动作 + 决策理由（从作业时间轴反推）
- 数据量：18080 条 SFT 样本，覆盖 3038 个关卡

### 1.2 问题本质

**用 MAA 作业当 SFT 训练目标，等于训练一个"复刻 MAA 的模型"。**

这违背了项目的核心需求——**"无作业推关"**：

| 维度 | MAA 作业 | 本项目目标 |
|------|----------|-----------|
| 决策依据 | 人工预设的固定动作序列 | 实时观察画面 + 检索知识 + 推理 |
| 泛化能力 | 只能跑作业覆盖的关卡 | 应能处理未见过的关卡/敌人组合 |
| 可解释性 | 作业无 reasoning，反推的理由是事后编造 | 必须输出真实的思考过程 |
| 适应性 | 作业失败时无法自主调整 | 应能根据局势变化动态调整策略 |

### 1.3 具体风险

1. **模式坍缩**：模型学会"看到 3-8 就按固定顺序部署"，而非理解"为什么这样部署"
2. **过拟合作业**：对作业覆盖的关卡表现好，对未覆盖关卡完全不会
3. **可解释性虚假**：反推的决策理由是"知道答案后编过程"，不是真实推理
4. **违背核心定位**：项目定位是"能看、能想、能打、能解释"的 Agent，不是"作业播放器"

---

## 二、MAA 作业的正确用法

MAA 作业**不是训练目标**，但仍然有价值：

| 用法 | 说明 | 状态 |
|------|------|------|
| ✅ 检索库（few-shot 参考） | Agent 决策时检索相似关卡的作业作为参考 | 保留 |
| ✅ 统计先验 | 干员出场频率、部署位置模式、费用-职业关系等统计规律 | 保留（见 docs/maa_decision_patterns.md） |
| ✅ 搜索启发式 | 推荐干员时用作业数据做协同过滤 | 保留 |
| ❌ SFT 训练目标 | 不再用作业动作作为训练 target | **暂停** |

---

## 三、新的 SFT 四类数据计划

SFT 该练的是**能力**，不是**动作复刻**。

### A. 结构化推理链

| 项 | 说明 |
|----|------|
| **练什么** | 输入游戏状态 → 输出 reasoning（思考过程）+ 候选方案（不是单一动作） |
| **数据来源** | 自举：强模型（Qwen3-8B-Thinking）生成推理链 → 私服验证筛选（只保留推理逻辑自洽的） |
| **数据格式** | `{"question": "状态描述", "answer": "reasoning + 候选方案 + 优劣分析"}` |
| **关键要求** | answer 必须包含多候选对比（至少 2 个方案），不能只给一个动作 |
| **预估数据量** | 5000-10000 条（覆盖主要关卡类型和敌人组合） |
| **验证方式** | 人工抽查 reasoning 是否逻辑自洽，候选方案是否合理 |

### B. 证据分级

| 项 | 说明 |
|----|------|
| **练什么** | 模型学会区分 fact / retrieved / inferred / estimated / unknown，什么时候该说"不知道" |
| **数据来源** | PRTS 数值 → fact；攻略文本 → retrieved；均匀估算 → estimated；模型推断 → inferred |
| **数据格式** | `{"question": "这个敌人的防御是多少？", "answer": "碎骨的防御为 200（evidence: fact，来源 PRTS 敌人面板）"}` |
| **关键要求** | 每条 answer 必须标注 evidence 级别和来源；不确定时必须说"不知道"而非编造 |
| **预估数据量** | 3000-5000 条（覆盖干员/敌人/关卡的常见查询） |
| **验证方式** | 检查 evidence 标注是否准确，是否有编造数值的情况 |

### C. 工具调用

| 项 | 说明 |
|----|------|
| **练什么** | 学会"先查再答"——什么时候该调用 query_operator / search_guide / recommend_operators |
| **数据来源** | 从 Agent 运行日志抽成功轨迹（调用了工具且结果被正确使用的决策） |
| **数据格式** | `{"question": "状态描述", "answer": "调用 query_stage(3-8) 获取敌情 → 调用 recommend_operators(3-8) 获取推荐 → 综合决策"}` |
| **关键要求** | 必须包含工具调用序列和调用理由；不能跳过工具直接给答案 |
| **预估数据量** | 2000-3000 条（需要先积累 Agent 运行日志） |
| **验证方式** | 检查工具调用是否必要、参数是否正确、结果是否被使用 |
| **依赖** | 需要先跑通 Agent 闭环，积累运行日志 |

### D. 战术常识

| 项 | 说明 |
|----|------|
| **练什么** | 游戏基本原则——"减法抗敌人别用法伤"、"先锋回费后撤退"、"医疗放在后排"等 |
| **数据来源** | 攻略/视频文本 → LLM 抽规则 → 人工审核 |
| **数据格式** | `{"question": "面对高防御敌人应该用什么类型干员？", "answer": "用术师（法术伤害无视防御）。原则：法伤克高防，物伤克低防高血量。evidence: inferred（战术原则）"}` |
| **关键要求** | **只说原则，绝不绑坐标**；原则必须可泛化，不能是"3-8 放在 A3"这种具体操作 |
| **预估数据量** | 1000-2000 条（覆盖职业克制、费用管理、部署顺序、技能时机等） |
| **验证方式** | 人工审核规则是否正确、是否泛化、是否有绑坐标的情况 |
| **数据来源补充** | 血狼破军等第三方分析视频（video_extract 提取） |

## 四、数据量与优先级

| 类别 | 预估数据量 | 优先级 | 依赖 |
|------|-----------|--------|------|
| A. 结构化推理链 | 5000-10000 | P0（核心） | 强模型自举 + 私服验证 |
| B. 证据分级 | 3000-5000 | P0（核心） | PRTS 数据已有 |
| C. 工具调用 | 2000-3000 | P1 | Agent 闭环运行日志 |
| D. 战术常识 | 1000-2000 | P1 | 攻略/视频文本 + 人审 |

**总计：11000-20000 条**（与原方案 18080 条量级相当，但质量更高）

## 五、执行计划（待确认后执行）

### Phase 1：B + D（不依赖 Agent 运行）
1. B 类：从 PRTS 数据生成证据分级训练对（脚本化，可批量生成）
2. D 类：从攻略文本 + 血狼破军视频提取战术规则（LLM 抽规则 + 人审）
3. 预计 1-2 周完成

### Phase 2：A（自举推理链）
1. 用 Qwen3-8B-Thinking 对典型游戏状态生成推理链
2. 私服验证筛选（逻辑自洽性检查）
3. 预计 2-3 周完成（强模型推理较慢）

### Phase 3：C（工具调用轨迹）
1. 跑通 Agent 闭环，积累运行日志
2. 从日志中抽取成功的工具调用轨迹
3. 预计 1-2 周完成（依赖 Agent 闭环）

### Phase 4：训练与评估
1. 合并四类数据，训练 SFT
2. 评估：推理质量、证据分级准确率、工具调用正确率、无作业推关能力
3. 与原方案（MAA 作业训练）对比
