# MAA 作业决策模式统计分析

> **数据性质说明**：本文统计的是"MAA 作业里的干员出场频率"，不是"干员强度榜"。
> 作业倾向于低配/常驻干员，新干员覆盖率低。强度评估请参考血狼破军等第三方分析
> （待 `video_extract` 模块提取视频图表数据后补充）。

> **干员本体 vs 召唤物/装置**：统计时用 `data/prts_raw/operators/` 目录的文件名（460 个）
> 作为干员白名单，在白名单中的为干员本体，不在白名单中的为召唤物/装置（弦惊、障碍物、幻影等）。
> 部分异格干员可能因文件名差异被误分类，需人工核对。

> **时间维度局限**：SFT 数据的 `meta` 中没有 `upload_time`/`publish_time` 字段，
> 无法按时间分组统计新干员出场趋势。如需时间维度分析，需重新抓取 MAA 作业时保留时间戳。

**数据来源**：`data/sft_data/sft_all.jsonl`（18080 条专家操作，来自 MAA 作业站 K=1 抓取）
**统计日期**：2026-09-27
**统计脚本**：`scripts/analyze_maa_patterns.py`
**原始数据**：`results/maa_patterns/stats.json`（gitignored）

## 四、新干员出场趋势（时间维度）

**结论：当前数据无法按时间分组。**

SFT 数据的 `meta` 字段包含：`stage`、`source_job`、`index`、`action`、`kills`、`operator`、`location`、`direction` 等，但**没有 `upload_time` 或 `publish_time` 字段**。

`source_job` 是作业名称（如"TO-S-4 - "家族聚会" 第二版"），不包含时间戳。因此无法按"近3个月/近半年/近一年"分组统计 EW、望、酒神等新干员的出场率变化。

**如需时间维度分析，需做以下工作**：
1. 重新抓取 MAA 作业时，在 `maa_job_downloader.py` 中保留作业的发布时间字段
2. 在 `sft_data_prep.py` 中将时间字段传递到 SFT 样本的 `meta` 中
3. 重新生成 `sft_all.jsonl` 后再统计

**临时替代方案**：可以用干员的实装日期（从 PRTS 干员页面的"获得方式"或"实装时间"字段提取）作为代理变量，按实装日期分组统计出场率。但这需要额外的爬虫工作，且实装日期≠作业使用日期，参考价值有限。

## 五、部署干员职业分布

| 职业 | 次数 | 占比 |
|------|------|------|
| 近卫 | 2554 | 20.2% |
| 术师 | 2200 | 17.4% |
| 重装 | 1951 | 15.4% |
| 先锋 | 1559 | 12.3% |
| 医疗 | 1415 | 11.2% |
| 狙击 | 1354 | 10.7% |
| 特种 | 886 | 7.0% |
| 辅助 | 739 | 5.8% |

**对部署优先级占位规则的校准建议**：

当前 `fast_reactor.py` 的占位排序是：
```
先锋/近卫（阻挡）> 狙击/术师/重装（输出）> 医疗/辅助（辅助）
```

MAA 数据显示的**出场频率**排序是：
```
近卫 > 术师 > 重装 > 先锋 > 医疗 > 狙击 > 特种 > 辅助
```

但"出场频率"≠"部署时序优先级"。从部署时序数据（见第五节）看，96% 的部署在 kills 0-4（开局阶段），几乎所有干员都在开局快速部署，很难区分严格的先后顺序。

**建议**：占位规则可调整为更符合 MAA 数据的版本：
1. 先锋（回费，必须最先部署）
2. 近卫/术师（核心输出，MAA 出场率最高）
3. 重装（承伤，保护输出）
4. 医疗/狙击/辅助/特种（按关卡需求）

> 注意：这仍是基于统计的近似，具体部署顺序应结合关卡敌情和费用曲线动态决策。

| kills | 技能次数 | 占比 |
|-------|---------|------|
| 0 | 556 | 79.4% |
| 20 | 9 | 1.3% |
| 12 | 7 | 1.0% |
| 6 | 6 | 0.9% |

| 其他 | 104 | 14.9% |

**数据局限说明**：
- 79.4% 的技能在 kills=0 时触发，看起来异常。原因可能是：
  1. MAA 作业的技能触发条件很多是"部署后立即开启"或"自动触发"，此时 kills 还没增长
  2. kills 锚点的精度有限（以击杀数为锚，不是以时间为锚），无法精确捕捉"敌人进入攻击范围时开技能"的时机
  3. 部分作业的技能是"自动回复型"，部署后自然转好就开
- **结论**：技能时机数据的参考价值有限，V100 上线后应录制真实时间轴（以秒为锚）来校准技能时机。

## 十一、关键结论与建议

### 11.1 对 Agent 设计的建议

| 维度 | MAA 数据规律 | Agent 设计建议 |
|------|-------------|---------------|
| 动作类型 | deploy 89%，开局集中部署 | 开局阶段集中做部署决策，后续切换监控模式 |
| 部署时序 | 96% 在 kills 0-4 | 前 30 秒是决策关键窗口 |
| 职业偏好（干员本体） | 近卫>术师>重装>先锋>医疗 | 核心输出优先，先锋必须最先（回费） |
| 召唤物/装置 | 占 deploy 21.3%，"弦惊"最常见 | 区分干员部署和装置放置，装置通常有固定位置 |
| 部署位置 | 集中在中路 (5,3)-(6,4) | 开局优先考虑中路，根据敌人来向调整 |
| 朝向 | 左右略多于上下，无绝对主导 | 朝向基于敌人路径，不固定偏好 |
| 阵容规模 | 2-4 干员占 52% | 简单关卡用精简阵容，不过度部署 |

### 11.2 数据局限

1. **kills 锚点精度有限**：以击杀数为锚，无法精确捕捉时间维度的决策时机（如"敌人进入攻击范围时开技能"）
2. **技能时机数据失真**：79.4% 技能在 kills=0 触发，可能是"部署后即开"或自动技能，参考价值有限
3. **坐标系统不统一**：不同地图的网格坐标系可能不同，Top 坐标是跨地图统计的近似
4. **MAA 作业偏好在先**：MAA 作业本身有版本偏好（如煌/艾雅法拉出场率高可能是因为当前版本强），不代表永恒最优
5. **无时间字段**：meta 中无 upload_time/publish_time，无法按时间分组统计新干员趋势
6. **干员白名单可能漏异格**：部分异格干员可能因文件名差异被误分类为召唤物，需人工核对

### 11.3 后续工作

1. **V100 上线后录制真实时间轴**：以秒为锚，精确捕捉部署/技能/撤退的时机
2. **按关卡类型分组统计**：当前是跨关卡统计，后续可按主线/活动/剿灭分组
3. **部署优先级动态化**：结合关卡敌情（敌人类型/数量/来向）动态调整部署顺序，而不是固定排序
4. **补充时间字段**：重新抓取 MAA 作业时保留发布时间，支持新干员出场趋势分析
5. **召唤物归属标注**：为每个召唤物/装置标注所属干员或关卡机制来源
